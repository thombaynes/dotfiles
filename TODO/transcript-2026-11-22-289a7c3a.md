## Comparison with markdown preview

Markdown preview is a pure function of the buffer. `render-markdown` and `markdown-preview` take the text you're editing and draw it, with no outside inputs.

Helm isn't like that. The output depends on:
- the whole chart directory, not one file;
- one or more values files and `--set` overrides;
- helper templates in other files;
- things only the cluster knows (`lookup`, `.Capabilities`).

So a Helm preview can't render the buffer. It has to run `helm template` on the saved chart and show the result in a separate buffer, which makes it a derived view. It can also fail with template errors, and it has to be rerun after every change. That's slower and more fragile than markdown, so run it on demand or on save, not per keystroke.

## Caveat for `local-k8s`

Your bootstrap chart renders ArgoCD `Application` objects, and ArgoCD then renders the real charts using `valueFiles` from other repos plus `valuesObject`. Running `helm template` on the bootstrap chart therefore shows the Applications, not what reaches the cluster. To see the final manifests, you'd render each target chart yourself with those value files, or use `argocd app manifests` against a running cluster. That's a two-level render, which ties back to the nesting concern in `STRATEGY.md`.

## Same key for two commands

There's no problem as long as each mapping is buffer-local to its filetype. Vim picks the mapping for the buffer you're in, and which-key shows the description for that buffer.

Your markdown mapping is already `ft = "markdown"`. The Helm mapping is set only on yaml buffers that have a `Chart.yaml` somewhere above them, so the two never overlap.

A conflict would only happen if one of them were global, because a buffer-local mapping silently shadows a global one on the same keys. Both are local here, so nothing is shadowed. `<leader>h` stays free for git hunks.

## What it does

In a yaml file inside a chart, `<leader>mp` finds the chart root and runs `helm template` there. It uses the chart's own `values.yaml`. It runs async, so it can't lag typing, and it saves the buffer first if it's modified. The output opens in a read-only YAML split. If you press it again, it reuses the same split. If Helm fails, the error shows in the split and you get a notification.
